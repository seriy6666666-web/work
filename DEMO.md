# Демонстрация «БЕЛМИ ЭНЕРДЖИ» — сценарий показа

Система управления производством литий-ионных АКБ. Пять ролей, полный цикл: заказ → операции → распределение по людям → выполнение на смене → статистика и предупреждения.

---

## 0. Запуск (за 5 минут до показа)

```bash
docker compose up --build
```

Дождитесь строки в логах backend: **`Seed completed with demo content.`** — база уже наполнена демо-данными (сбрасывать ничего не нужно).

- Приложение: **http://localhost:5173**
- API: http://localhost:3000

> Полный сброс данных (если что-то натыкали в прошлый раз):
> `docker compose down -v && docker compose up --build`

**Все пароли демо-сотрудников: `password123`**

> Пароли задаёт администратор: в разделе «Пользователи» у каждой строки есть кнопка **«Пароль»**
> (можно сгенерировать вида `belmy-7413`). Сотрудникам, созданным импортом из Excel, система
> выдаёт каждому свой пароль и показывает список **один раз** — сразу после импорта, с выгрузкой
> в CSV для раздачи. Восстановить пароль потом нельзя: в базе только хэш, можно лишь задать новый.

> **Увольнение** — кнопка «В архив» в той же строке: вход закрывается, человек пропадает из распределения,
> смен, матрицы компетенций и целей, но его история остаётся в отчётах. Архивных видно по галочке
> «Показывать архив», вернуть в работу — одной кнопкой.

| Роль | Логин | Что показываем |
|------|-------|----------------|
| Начальник участка | `site_lead` | Флагман: распределение, компетенции, смены, оборудование, статистика |
| Начальник производства | `production_head` | Сводка по заводу, тренды, предупреждения, оборудование/склад |
| Планировщик | `planner` | Заказы, продукты-шаблоны, склад материалов |
| Рабочий | `worker` | Простой экран «мои задачи» (крупные кнопки) |
| Администратор | `admin` | Пользователи, участки, журнал аудита |

---

## 1. Начальник участка (`site_lead`) — 4-5 мин, главный экран

Вход → сразу открывается **«Распределение»**.

1. **Верхние карточки-метрики**: выполнение плана (95%), операций в работе (4/4), на смене (3 чел.), риск отставания.
2. **Операции участка** — 4 операции по заказам АКБ-48В/АКБ-24В:
   - прогресс-бары (85/100, 100/100 …), приоритет, срок;
   - назначенные сотрудники с аватарами и «X шт выполнено»;
   - выпадающий список **учитывает компетенции** — кто без навыка помечен «нет навыка».
   - *Живьё:* назначить свободного сотрудника на операцию «Тестирование» (85/100) → он появляется в списке.
3. **«Матрица компетенций»** — кто какими навыками владеет (для распределения).
4. **«Планирование смен»** — недельная сетка: клик по ячейке переключает пусто → Д (день) → Н (ночь). Данные на текущую неделю уже есть.
5. **«Оборудование»** — 4 единицы: рабочее, на обслуживании, **поломка** (красный). *Живьё:* переключить статус в «Поломка» → тост «начальник производства уведомлён».
6. **«Статистика»** — рейтинг сотрудников по **выработке от нормы** (объективная метрика, сопоставимая между разными операциями), плюс выполнение назначенного и **% брака**, выгрузка CSV. Нормы выработки на смену задаёт планировщик в разделе «Навыки».

---

## 2. Начальник производства (`production_head`) — 2-3 мин, взгляд «сверху»

1. **«Сводка участков»** — выполнение плана по участкам (график + таблица), переход в участок.
2. **«Тренды»** ⭐ — выпуск годной продукции по дням (столбики за 8 дней), доля брака по дням, сводка (310 шт / 10 брак / 3.1%). Переключение 7 / 14 / 30 дней.
3. **«Оборудование»** — состояние по всем участкам, счётчики поломок/обслуживания.
4. **«Материалы»** — остатки по складу, позиция **«Корпус АКБ» ниже порога** подсвечена.
5. **«Предупреждения»** — заказы под риском срыва срока и отстающие сотрудники.
6. **Колокольчик** (справа вверху) — если `site_lead` перед этим отметил поломку, здесь придёт уведомление в реальном времени.

---

## 3. Планировщик (`planner`) — 2 мин

1. **«Заказы»** — список заказов, статусы. Создать заказ **«из продукта»**: выбрать шаблон «АКБ-48В» → операции подставятся автоматически.
2. **«Продукты»** — шаблоны маршрутов (какие операции на каких участках).
3. **«Материалы»** — склад: приход/расход по кнопкам; при падении ниже порога — уведомление. *Живьё:* списать «Корпус АКБ» в расход → тост о низком остатке.

---

## 4. Рабочий (`worker`) — 1 мин, «для людей без опыта с ПО»

Специально максимально простой экран: крупные кнопки, «Отметиться на смене», список задач, ввод «годных / брак, шт». Контраст с плотными дашбордами руководителей — это по ТЗ.

---

## 5. Администратор (`admin`) — 1 мин

Пользователи, участки, **журнал аудита** (кто что менял — все действия логируются).

---

## Что подчеркнуть по технике

- **Реальное время** — доска распределения и колокольчик обновляются по WebSocket без перезагрузки.
- **Роли и права** — каждый видит только своё; API закрыт guard'ами (можно показать 403).
- **Авто-статусы заказов** — CREATED → IN_PROGRESS → DONE считаются автоматически по выполнению.
- **Тёмная тема** — переключатель справа вверху.
- **Адаптивность** — на узком экране сайдбар сворачивается в бургер-меню.
- **Надёжность** — миграции и seed применяются автоматически при старте; ежедневный бэкап БД (сервис `backup`).

## Если что-то пошло не так

| Симптом | Что сделать |
|---------|-------------|
| Экраны пустые | Данных нет → `docker compose down -v && docker compose up --build` |
| Порт занят | Остановить прежний запуск: `docker compose down` |
| «Не открывается 5173» | Дождаться сборки frontend; проверить `docker compose ps` (все `running`) |
| Не входит в аккаунт | Пароль у всех `password123`; логин строчными буквами |
