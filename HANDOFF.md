## 1. Поднять проект (10 минут)

```bash
git clone https://github.com/seriy6666666-web/work.git belmy
cd belmy
docker compose up --build -d
```

Файл `.env` **не нужен** — значения по умолчанию прописаны в `docker-compose.yml`.
Приложение: http://localhost:5173, API: http://localhost:3000.
Дождитесь в логах бэкенда строки `Seed completed with demo content.` — база наполнится
демо-данными сама (миграции и сид запускает `backend/docker-entrypoint.sh`).

Пароль всех демо-сотрудников — `password123`, логины в [DEMO.md](DEMO.md).

### Если нужны сегодняшние данные, а не свежий сид

На **этом** компьютере до отъезда:

```bash
docker compose exec -T postgres pg_dump -U belmy belmy > belmy-dump.sql
```

Перенести файл (флешка, облако — в git не класть) и на ноутбуке:

```bash
docker compose exec -T postgres psql -U belmy -d belmy < belmy-dump.sql
```

Без этого данные будут чистые демонстрационные — для разработки этого достаточно.

## 2. Чтобы кодить, а не только смотреть

```bash
cd backend && npm ci && npx prisma generate
cd ../frontend && npm ci
```

Проверки:

```bash
cd backend && npx tsc --noEmit && npx jest        # типы + 9 unit-тестов
cd frontend && npm run build                      # ОБЯЗАТЕЛЬНО так, не tsc --noEmit
cd frontend && npx playwright test                # 28 сценариев, нужен поднятый docker
```

**Важно:** фронт проверять только через `npm run build`. `tsc --noEmit` пропускает ошибки,
которые ломают сборку в Docker — уже наступали на это.

### Миграции Prisma

`prisma migrate dev` в этом окружении не работает неинтерактивно. Порядок такой:

```bash
cd backend
mkdir -p prisma/migrations/$(date +%Y%m%d%H%M%S)_имя_миграции
npx prisma migrate diff --from-config-datasource --to-schema prisma/schema.prisma --script > prisma/migrations/<папка>/migration.sql
npx prisma migrate deploy && npx prisma generate
```

Вывод писать **только** через `>`, без `| head` — обрежет файл на середине и миграция
упадёт с `unterminated quoted identifier`.

## 4. Что решено, но НЕ сделано — продолжать отсюда

### 4.1 Выпадающие списки (решение принято, код не написан)

Заказчику не нравится вид системных `<select>` — их 32 штуки на 14 экранах, Windows
рисует их своим синим и они выбиваются из интерфейса.

**Что делать:**

1. Свой компонент `Select` вместо всех native: та же рамка/фон/скругление, что у полей
   ввода, шеврон вместо системной стрелки, строки 38-40 px, выбранное — галочкой
   **справа** (слева читается как множественный выбор), клавиатура (стрелки, Enter, Escape).
2. `SearchSelect` привести к тому же виду — сейчас поиск и обычные списки выглядят по-разному.
3. В выборе сотрудника на распределении — **вариант В**: показывать только владеющих
   навыком, остальные под ссылкой «Показать без навыка (N)». Галочки `✓` и подписи
   «нет навыка» убрать совсем — одно и то же помечено дважды.
4. Тесты: часть использует `selectOption`, который работает только с native — переписать.

**Риск:** на планшете системный список открывается крупным колесом, по нему удобно
попадать пальцем. Если рабочим станет неудобно — вернуть native **только** на экране рабочего.

### 4.2 Разделение по площадкам (план согласован, код не написан)

Это следующий большой заход, сопоставим с эпиками 4-6.

**Как устроено производство (со слов заказчика):**

- Адреса: ЮП26, ЮП33, скоро ЮП14. Отдельно лаборатория — её пока не трогаем.
- Участки: **призма, цилиндры, заготовки**. Всё. ОТК, лаба, инженеры-конструкторы,
  технолог — отдельные подразделения, в системе их пока нет.
- Призма — на **двух** адресах, ЮП26 и ЮП33. У призмы **на каждом адресе свой начальник участка**.
- Цилиндры — на ЮП33, там начальник участка **и зам начальника участка**.
- Заготовки — физически на ЮП33, снабжают обе площадки.
- Планы: цилиндры целиком переедут на ЮП14, ЮП26 останется под призму. Сроки неизвестны.

**Главный вывод:** связь участок↔площадка — многие-ко-многим и меняется во времени.
Простое поле «у участка есть площадка» не годится: призма в него не влезает.

**Что делать:**

1. Адрес (`platformId`) появляется у **сотрудника**, у **оборудования** и у **операции**.
   Участок остаётся тем, что он есть.
2. Начальник участка **с проставленным адресом** видит только свой адрес: распределение,
   компетенции, планирование смен, цели, журнал прихода-ухода, статистику, старших смен,
   переводы. **Без адреса** — весь участок, как сейчас. Так призма разделится на двух
   начальников, а цилиндры и заготовки не сломаются.
3. Списание материалов перевести с площадки **заказа** на площадку **операции**.
   Сейчас это дыра: заказ на одном адресе, сделали на другом — списался чужой склад.
4. Предупреждение при назначении человека с чужого адреса.
5. Админка: поле «площадка» у сотрудника и оборудования, колонка в списке.
6. Начальник производства: фильтр по адресу в сводке участков.
7. Данные: площадки в базе сейчас демонстрационные («Площадка Минск», «Площадка Гомель») —
   переименовать в ЮП26 и ЮП33, ЮП14 добавить, когда появится.

**Зам начальника участка** решено не делать отдельной ролью: это второй `SITE_LEAD` на том
же участке и адресе, а в иерархии ему проставляется руководителем начальник участка. Права
те же — зам для того и нужен, чтобы подменять. Если позже окажется, что зам чего-то делать
не должен, тогда заведём роль.

## 7. Что полезно знать про решения, которые уже приняты

- **Пароли.** Админ задаёт вручную или генерирует вида `belmy-7413` — такой диктуют вслух
  и набирают на терминале в цеху. Импорт из Excel выдаёт каждому свой пароль и показывает
  список **один раз** с выгрузкой в CSV. Восстановить пароль нельзя, только задать новый.
- **Архив вместо удаления.** Сотрудника с историей производства удалить нельзя — только в
  архив: вход закрывается, из рабочих списков пропадает, в отчётах остаётся.
- **Лимит входов 300/мин** (был 30). Вся смена заходит через один шлюз завода, на старте
  смены 100 человек логинятся в одну минуту.
- **Норма выработки** — штук за смену (8 часов). Если человек ушёл раньше, это его дело,
  норма не пересчитывается.
- **Обращения** читает только администратор. Анонимность честная: при галочке автор не
  сохраняется вовсе, остаются роль и участок.
