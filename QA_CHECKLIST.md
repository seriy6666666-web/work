# QA-чеклист приёмки — BELMY ENERGY

Ручная проверка перед релизом. Автотесты покрывают выделенное **[авто]** —
их достаточно прогнать командами, остальное проверяется руками.

## Запуск тестов
- **Бэкенд юнит-тесты:** `cd backend && npm test`
- **E2E (нужен запущенный стек на :5173 и :3000):** `cd frontend && npm run test:e2e`
- **Типы:** `cd backend && npx tsc --noEmit` · `cd frontend && npx tsc --noEmit -p tsconfig.app.json`
- **Линт:** `cd frontend && npx oxlint src`

---

## 1. Аутентификация и роли
- [ ] **[авто]** Логин каждой роли (admin/planner/production_head/site_lead/worker) ведёт на свой раздел.
- [ ] **[авто]** Неверный пароль → тост с ошибкой, вход не выполнен.
- [ ] Прямой переход на чужой раздел (например worker на `/admin/users`) — редирект/запрет.
- [ ] После «Выйти» защищённые страницы недоступны, возвращают на логин.
- [ ] **[авто]** >300 попыток входа в минуту → 429 (лимит поднят под смену в 100 человек, входящую через один шлюз).

## 2. Администратор
- [ ] **[авто]** Создать участок → тост, появился в списке; удалить через модалку.
- [ ] Создать пользователя каждой роли; для site_lead/worker обязателен участок.
- [ ] Редактирование пользователя (ФИО, роль, участок, смена пароля).
- [ ] **[авто]** Поиск и сортировка в таблице пользователей.
- [ ] Журнал действий: мутирующие действия фиксируются (кто/метод/путь/код); пароль в теле вырезан; фильтры по методу/дате/пользователю; пагинация.

## 3. Планировщик
- [ ] **[авто]** Навык → заказ → операция → удаление (полный цикл).
- [ ] Операция с двумя участками (secondary site).
- [ ] Заказ нельзя удалить, пока есть операции.
- [ ] Смена статуса заказа сохраняется.

## 4. Начальник участка
- [ ] Матрица компетенций: отметка/снятие навыка сохраняется.
- [ ] **[авто]** Доска «Распределение»: 4 карточки-метрики + два столбца.
- [ ] Назначение сотрудника: компетентные вверху, некомпетентные помечены, отсутствующие скрыты/заблокированы.
- [ ] Подтверждение уважительной причины простоя → исключается из рейтинга.
- [ ] Отсутствия: добавить/удалить; отсутствующий не назначается.
- [ ] Переводы: запрос, подтверждение/отклонение донор-участком.
- [ ] Статистика: переключение периодов, график по сотрудникам, экспорт CSV (кириллица в Excel корректна).
- [ ] **Real-time:** пока открыта доска, отметка выполнения рабочим обновляет цифры без перезагрузки.

## 5. Начальник производства
- [ ] Сводка участков: % выполнения, график, проваливание в участок.
- [ ] Предупреждения: заказы в зоне риска и отстающие сотрудники.

## 6. Рабочий
- [ ] Отметка прихода на смену.
- [ ] Отметка выполнения (крупные кнопки, минимум действий).
- [ ] Простой с причиной и зоной ответственности.
- [ ] Самостоятельная отметка отсутствия.

## 7. Бизнес-правила (критично по ТЗ)
- [ ] **[авто]** Подтверждённый простой исключён из рейтинга (числитель и знаменатель).
- [ ] **[авто]** Заказ «в зоне риска»: прогресс + 15 п.п. < прошедшая доля времени.
- [ ] **[авто]** CSV: BOM + экранирование кавычек + пустая ячейка для null.

## 8. Интерфейс и надёжность
- [ ] Логотип не растянут (натуральные пропорции) на логине и в шапке.
- [ ] Сайдбар закреплён при прокрутке — карточка пользователя не уезжает.
- [ ] Адаптив: на узком экране сайдбар сворачивается в бургер-меню.
- [ ] **[авто]** Тёмная тема переключается и сохраняется.
- [ ] Скелетоны при загрузке, пустые состояния, тосты вместо системных алертов.
- [ ] Экран сотрудника корректен на планшете/телефоне.
